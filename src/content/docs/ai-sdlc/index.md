## Purpose

A pragmatic model for adopting agents in software delivery, from teams to the organization.

## Team level

Enable reliable delegation of engineering work to agents.

### Team harness

What a team maintains so agents can work reliably in its project.

| Element       | Role                                                          |
| ------------- | ------------------------------------------------------------- |
| **Context**   | Instructions and project knowledge that steer agent behavior. |
| **Workflows** | Skills and tasks that standardize how agents work.            |
| **Sensors**   | Checks and rulesets that verify agent output.                 |

### Team capabilities

Expand agent use from local development to autonomous implementation.

| Capability                    | Application                                                                      |
| ----------------------------- | -------------------------------------------------------------------------------- |
| **Assisted development**      | Coding agents help developers implement, test, refactor, and understand code.    |
| **Automated review**          | Agents review changes, first as feedback, later as enforced gates.               |
| **Incident intelligence**     | Agents analyze incidents, triage findings, and create or enrich tickets.         |
| **Autonomous implementation** | Agents implement bounded tasks, run checks, and submit changes for human review. |

## Organization level

Make agent adoption reusable, governed, and safe across teams.

### Organization harness

What the organization curates so teams reuse it instead of building their own.

| Element       | Role                                                              |
| ------------- | ----------------------------------------------------------------- |
| **Workflows** | Shared skills and tasks that standardize how agents work.         |
| **Templates** | Component templates with agent context and verification built in. |

### Organization capabilities

Govern access to models, curate skills and tools, and isolate agent execution.

| Capability             | Application                                                                      |
| ---------------------- | -------------------------------------------------------------------------------- |
| **Centralized access** | Governed access to approved models and tools, with budgets and usage visibility. |
| **Curated registries** | Catalogs of approved skills and tools, with review and versioning.               |
| **Safe execution**     | Sandboxed environments and traceability for agent workloads.                     |
